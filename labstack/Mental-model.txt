## 3️⃣ End-to-end architecture (minimal, scalable)

### 🧩 Services required (ONLY what you need)

### 1️⃣ `catalog-service` (background / cron)

**Purpose:** Sync LabStack Network APIs

Calls:

* getPackages
* getPackage
* getTests
* getTest
* getLabs (optional)
* getPackagePreparations

Writes to DB only.

📌 Runs:

* once on deploy
* nightly cron (later)

---

### 2️⃣ `diagnostic-api` (user-facing, synchronous)

**Purpose:** Everything FE talks to

Responsibilities:

* Return catalog (from DB)
* Serviceability
* Slots
* Quote / price calculation
* Create order (after payment)
* Cancel / reschedule order
* Fetch order status (from DB)

Calls LabStack:

* checkServiceability
* getSlots
* placeOrder
* cancelOrder
* rescheduleOrder (later)

---

### 3️⃣ `payment-service` (or shared service)

**Purpose:** Payments + idempotency

Responsibilities:

* Create payment intent
* Verify payment
* Prevent duplicates

📌 LabStack does NOT handle payment.

---

### 4️⃣ `webhook-handler` (async)

**Purpose:** Order lifecycle updates

Responsibilities:

* Receive LabStack webhooks
* Update order status
* Store reports
* Trigger notifications

Calls LabStack:

* getOrderDetails (fallback)
* getReport (on demand)

## 4️⃣ Complete flow (happy path, step-by-step)

### 🔵 Phase 0 — Catalog Sync (offline)

```
catalog-service → LabStack Network APIs
               → DB (packages, tests, prices)
```

---

### 🟢 Phase 1 — User browsing

```
FE → diagnostic-api → DB
```

Returns:

* packages
* tests
* prices
* tags

❌ No LabStack call here

---

### 🟡 Phase 2 — User selects test/package

* FE sends selected IDs
* Backend stores selection (optional)

No dependency on availability yet.

---

### 🟠 Phase 3 — Serviceability

```
FE → diagnostic-api
   → LabStack checkServiceability
```

Returns:

* serviceable labs
* HOME / CENTER

---

### 🔵 Phase 4 — Slots (optional but recommended)

```
FE → diagnostic-api
   → LabStack getSlots
```

Returns:

* time slots

---

### 🟣 Phase 5 — Price resolution (backend only)

Backend computes:

```
selected items
∩ labs supporting them
∩ serviceable labs
↓
final amount
```

Returns:

```json
{
  "quoteId": "q_123",
  "amount": 3799
}
```

---

### 🟤 Phase 6 — Payment (idempotent)

```
FE → Payment Gateway
payment_id (unique)
↓
BE verifies payment
```

Store:

* payment_id
* amount
* status

---

### 🔴 Phase 7 — Order placement

```
diagnostic-api → LabStack placeOrder
```

Store:

* internal_order_id
* labstack_order_id
* status = ORDER_INITIATED

---

### 🟢 Phase 8 — Webhooks (truth)

```
LabStack → webhook-handler
```

Updates:

* ORDER_SCHEDULED
* PHLEBO_ASSIGNED
* SAMPLE_COLLECTED
* REPORT_DELIVERED

DB becomes **source of truth**.

---

### 🔁 Phase 9 — Cancellation / Reschedule

```
FE → diagnostic-api
   → LabStack cancelOrder / rescheduleOrder
```

Webhook confirms final state.
